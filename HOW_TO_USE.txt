HOW TO USE: second-brain-commands
===================================

PURPOSE
  Provide a standardized, fast slash-command and prompt system for interacting
  with your personal Second Brain MCP server across all AI apps on this PC
  (Claude Desktop, Claude Code, Grok CLI, Antigravity/Gemini, and Cursor).
  Enables instant semantic retrieval, memory lookups, dated note append,
  knowledge graph exploration, and lifecycle management while strictly enforcing
  the mandatory pre-edit approval policy.

CAPABILITIES
  - Instant semantic recall with intent-framing and graph expansion (--hops)
  - Full un-truncated content inspection via entry ID
  - Chronological browsing of recent memories, tasks, and decisions
  - Knowledge graph traversal to discover directly linked memories
  - Structured memory creation with inline hashtags (#work, #task) and volatility flags (!durable, !state, !volatile)
  - In-place appending of progress updates with automatic date-stamps
  - Safe memory updates, deprecation/canonical status management, and permanent deletion
  - Universal pre-edit safety gate: always displays exact text, tags, volatility, and rationale before touching write tools
  - Automated session synchronization briefings (/brain sync) and multi-topic digests (/brain digest)

USE CASES
  - "What did we decide about the Live Actions UI architecture last week?"
  - Quickly storing a new studio workflow, shortcut, or project constraint
  - Checking recent commitments before starting a coding session
  - Tracing the evolution of a decision through linked memories in the graph
  - Changing an outdated decision to deprecated so it won't pollute future recalls
  - Running identical second brain commands across Claude, Grok, and Antigravity

IDEAS
  - Type `/brain sync` at the beginning of any chat to immediately prime the AI
  - Use `/brain save [note] #task !state` when agreeing on a new to-do item
  - Pair `/brain recall [topic] -h 1` when investigating why a architectural choice was made
  - Run `/brain digest` on Monday mornings to see what was captured across all sessions
  - Use `/brain status [id] canonical` to lock critical foundational decisions against overwrites
